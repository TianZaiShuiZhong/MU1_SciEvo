# Sci-Evo 数据集技术报告（草稿 v0.2）

## 1. 数据集概述

- 数据集名称：`MU1-SciEvo-MultiPaper-Draft`
- 赛道类型：`Sci-Evo`
- 研究领域：`蛋白质工程 + 科学机器学习 + 等离子体物理`
- 应用场景：
  - 科学问题建模与推理链学习
  - 科学文献中的“问题-方法-结果”闭环抽取
  - 训练/评测科学智能体的草稿轨迹生成能力
- 当前版本：`v0.2.0`
- 记录规模：`12 条记录（>=10）`
- 数据划分：`train=8, valid=2, test=2`

## 2. 数据来源与合规说明

- 来源形态：公开论文 PDF（本地下载后，经 MinerU 解析为 Markdown）
- 当前覆盖论文（去重后 3 篇）：
  - `Denovo design of luciferases using deep learning`
  - `Laboratory study of the failed torus mechanism in arched, line-tied, magnetic flux ropes`
  - `IELM: An Open Information Extraction Benchmark for Pre-Trained Language Models`
- 合规策略：
  - 保留来源 URL/本地文件 URI、task_id、解析路径、构建版本等追溯字段
  - 所有结构化字段来自论文原文片段，不伪造实验结果
  - 当前版本为 `draft`，明确标注需人工复核字段

## 3. 数据结构设计（Schema）

数据结构由 [scievo.schema.json](/C:/Users/zheng/Desktop/MU1_SciEvo/schemas/scievo.schema.json) 定义，核心字段：

- `initial_request`: 任务目标、输入信息、意图、量化目标
- `trajectory`: 多步轨迹（problem_formulation / method_design / result_validation）
- `success_verification`: 验证方式、指标、结论
- `provenance`: 创建时间、pipeline 版本、MinerU task_id、来源片段
- `quality`: 审核状态与质量分数

## 4. 数据构建流程

1. 准备论文列表（URL 或本地 PDF）。
2. 使用 MinerU 解析：
   - 精准 API：`/api/v4/extract/task`
   - 本地上传 API：`/api/v1/agent/parse/file`
3. 下载 `full.md` 到 `data/interim/markdown/<paper_id>/`。
4. 运行多论文草稿构建脚本，生成 `scievo_multi_paper_draft.jsonl`。
5. 运行 schema 校验和数据切分。

## 5. MinerU 使用说明（满足赛题要求）

- 使用工具链：`MinerU API`
- 使用模式：
  - `precise`（带 token，解析样例文献）
  - `agent_file`（本地签名上传，批量解析多论文）
- 本次实际任务 ID（示例）：
  - `bb6f42b9-f7eb-4322-af3b-717bf05cb642`（precise）
  - `6c381b48-2513-4100-b70e-7b055872015d10`（agent_file）
  - `6fbc3486-89b4-4f72-9862-8f194574147b10`（agent_file）
  - `e165283f-33d6-4a11-8368-eb447ae7ab3d10`（agent_file）

## 7. 质量评估方法

- 结构完整性：JSON Schema 通过率（当前为 100%）
- 可追溯性：每条记录带 `task_id + source_span + source.url`
- 可复现性：脚本化流水线可重复执行
- 人工复核状态：当前全部标记为 `draft`

## 8. 与评分维度对齐

- 科学表达与推理链：显式建模 1-3 步问题-方法-结果链
- 科学价值与创新：跨领域科学论文统一结构化
- AI-Ready：JSONL + Schema + split 文件
- 工程质量：自动化脚本 + 校验 + 可追溯中间产物
- 开放共享：代码与流程可直接开源（注意移除 token）
